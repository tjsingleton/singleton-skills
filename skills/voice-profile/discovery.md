# Discovery tracks

Run one track only when the user names it. Ask for their artifacts. Do not
fill gaps with invented samples.

## my-voice

Ask for 5–10 real samples (email, post, docs, casual). Analyze and propose
registers, sentence patterns, anti-patterns, and when to switch. Review with
them before writing `registers.md`. Technical accuracy still beats voice.
Then draft one short email and one short post on topics they give, for grading.

## pro-authorship

Build rules only from accepted work, rejected versions, and repeated
corrections. Every rule is observable (two-reader test). Quality-words get
unbundled against excerpts. One accepted piece is held-out and never analyzed.
Propose 5–10 rules with excerpts; take confirm / reject / narrow. Keep the
profile draft until the held-out test passes. No theater in deliverables.

## audience-content-system

Interview for publication, audience floor/ceiling, formats, cadence, and 2–3
pieces that landed. Then templates plus a batch-planning mode. Calibration:
would the least technical reader follow every step?

## plain-english-docs

If they want this as a standalone skill, copy `plain-english.md` into its own
skill folder. Test by rewriting one existing paragraph from the current repo
and showing both versions.
