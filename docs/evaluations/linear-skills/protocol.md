# Linear skills human pilot

TJ-149 evaluates draft comprehension using two synthetic comparisons. The participant packet contains complete controlled source wording and exact agent-composed revisions. It contains no answer key. The facilitator key is separate. No live issue edits are part of this pilot.

## Run in chat

1. Explain that these are synthetic snapshots, not copied live issues. Ask the participant to avoid the facilitator key until finished.
2. Show pair A original alone. For that version, ask the participant to identify the next action, explain remaining acceptance work, and locate the evidence for a completion claim, including what it cannot establish. Ask for reading/answering time in seconds, or “not measured,” and anything confusing.
3. Show pair A revised alone and ask the same three tasks, time, and confusion questions. Record order as original then revised. Keep earlier answers visible only if the participant chooses; record whether they referred back.
4. For pair B, show revised first, then original, repeating the three tasks and time/confusion questions for each version. This reverses order across pairs but does not remove learning effects.
5. After both pairs, ask which version made each task easier, what requirements or limits appeared lost or changed, and whether the participant would adopt, revise, or defer this format, with a reason.
6. Compare responses against the facilitator key only after answers are recorded. Separate participant misunderstandings from facilitator inferences. Check the preservation ledger alongside readability. Route a concrete defect to its owning skill, repair only that behavior, run its affected scenario again, then rerun the affected human comparison when needed.

A response can answer all three tasks in one message. Readability preferences alone cannot establish requirement preservation. A single participant and two short examples establish only bounded usability evidence. This pilot does not certify hosts, live writes, or operational acceptance.

## Private observation record

Keep raw participant wording and identifiable context outside the public repository. For every presented version retain: pair/version, displayed revision and hashes, presentation order, task answers, self-reported seconds or not measured, confusion, assistance, rereading, and participant-reported omissions. Tool latency and chat timestamps are not participant reading time. Missing responses stay pending; never fill them with an agent answer.

For each task record an observed correct/partial/incorrect/unclear assessment, the supporting private response reference, and the facilitator's rationale. Preserve disagreement and uncertainty. A small sample does not support a population speed estimate or causal claim.
