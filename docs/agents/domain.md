# Domain docs

This repository uses a single-context layout.

Before exploring an area, read the root `GLOSSARY.md` and relevant decisions
under `docs/adr/`, when present.

If either is absent, proceed without creating placeholder documents.
Create domain documentation when terms or decisions are actually resolved.

Use the glossary's vocabulary in specifications, issues, and implementation
work. If a proposed change conflicts with an ADR, surface the conflict
explicitly rather than silently overriding the decision.
